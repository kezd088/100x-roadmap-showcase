## ✦ 01 / 从一句提示词，到可交接的方法

一次得到不错的结果，并不代表下一次能复现。方法需要清楚的输入、过程、输出和检查方式。

### 为什么需要它

视频分析、脚本分段、语言改编、人物设定和生成提示词经常分散在不同对话里。100xSKILL 把这些内容工作整理成可重复执行的 Skill，使 Agent 知道从哪里开始、要保留哪些证据，以及怎样把结果交给下一步。

### 当前公开载体

以 100x-skill-tiktok 技能框架为代表，面向 TikTok / UGC 内容生产。当前公开目录包含 8 个功能 Skill 和 1 个路由入口；框架与通用方法公开，内部语料、校准资产和客户原始材料保持私有。

### 谁会用到，交付什么

适合内容创作者、跨语言内容团队和为 Agent 设计工作流的人。输出包括结构化分析、分段稿、人设与场景说明、搜索词、改编稿和生成提示词；它们是可继续处理的工作产物。

## ✦ 02 / 八个功能，按工作阶段理解

不必一上来安装或执行全部流程。先根据当前材料与目标，选择最适合的一步。

![100xSKILL 工作流程与角色图解](overview.png)

### 读懂素材 / 视频反推与脚本分段

100x-video-reverse 从本地视频组织可回查的证据包，并提供 HTML 与 Markdown 交接；100x-segment 处理口播文本的分段与表达节奏。一个从视频出发，一个从文本出发，输入条件不同。

### 调整表达 / 本地化、人物与夸张

100x-localize 负责目标市场的表达改编；100x-persona 整理讲述人物和场景；100x-exaggerate 处理夸张与反差表达。输出仍需回看原始材料和语境，不能把改编当成可以凭空添加产品事实。

### 准备视觉 / 搜索词、裂变与提示词

100x-search-query 为找参考材料组织搜索短语；100x-visual-fission 基于锁定参考展开视觉变体；100x-prompt-compose 将模板与变量组合为生成提示词。前一步的材料和约束应保留到后一步。

### 路由入口 / 先判断做哪一步

100x-tiktok 用于判断任务应从哪个 Skill 开始，以及结果之后可以进入哪里。它是路由入口，不单独承担内容生成。具体输入、输出和依赖以公开仓中的各 Skill 说明为准。

## ✦ 03 / 案例：把一段口播改成目标市场版本

以下为方法示例。使用合成脚本或已获准的材料，不把真实客户原稿作为公开演示。

### 任务简报

> 为一段保温杯口播准备目标市场版本。输入包括原文、产品可证实的信息、目标语言与受众、必须保留的内容，以及不能添加的承诺。若有参考视频，还需说明可以使用的素材范围。

### 01 / 先分析结构与证据

判断从文本分段还是视频反推开始。整理每一段在表达什么、依据来自哪里，区分观察到的内容和推断。证据不足时标明缺口，不用流畅文字补造事实。

### 02 / 再处理市场与人物表达

根据目标受众调整语言、人设和场景，让表达符合用途。保留原有产品事实，检查语义是否因改写而改变；涉及夸张和反差时，仍要核对表达边界。

### 03 / 把结果交给制作

在已确认的脚本与参考基础上整理镜头或提示词。交接时说明使用了哪些输入、有哪些待确认项，以及哪份输出是供人工审核、哪份是供生成工具使用。

### 建议验收口径

能从输出找回依据，关键字段齐全，事实没有被改写成不存在的承诺，下一位协作者知道怎样继续。结构检查通过只说明一部分质量，仍需要语义与用途审查。

## ✦ 04 / 可执行的检查，为什么重要

公开框架把约束写进输出结构和校验方法，但不把自动检查当成对内容正确性的全包保证。

### 结构层：输出能否被正确使用

JSON Schema 用来约束必需字段、类型、枚举和额外字段等结构问题。清楚的输出契约能减少后续步骤猜测字段含义，也方便把生成结果交给程序或另一个 Skill。

### 规则层：字段之间是否成立

有些要求涉及引用、跨条目关系或证据对应，需要额外的校验脚本。两层检查分别负责结构和关系，避免把所有判断压在一段自然语言说明里。

### 人工层：语义与质量仍需判断

字符串引用存在，不代表摘录后没有改变含义；结构齐全，也不代表内容有用。应结合原材料检查语义、表达强度和实际用途，不能把验证器通过写成效果已经验证。

### 方法、数据与工具分别管理

SKILL 提供方法；私有语料与校准资产提供业务上下文；MCP 等工具执行外部能力。公开框架可以被了解与采用，但不意味着内部数据会随之交付。

### 第一次使用建议

> 先从一个明确输入开始，选一个 Skill，查看输出说明，再运行对应的检查方法。安装、依赖与版本要求以公开仓为准；没有必要为了一个任务先串起整套生态。

## ✦ 05 / 可以从哪些工作参与

适合公开协作的重点是通用方法、合成样例、契约和可复现问题。

### 任务 A / 合成样例与反例

为一个 Skill 准备正常输入和有针对性的错误输入，例如缺少证据、字段矛盾或输出为空。交付预期结果与检查说明；反例应能暴露实际规则缺口，而不是只让程序因文件缺失报错。

### 任务 B / 输出契约与交接

检查一个 Skill 的输出是否足够让下一步继续工作，说明字段含义、依赖材料与未解决问题。交付结构样例和交接说明，以另一位协作者能否正确使用结果为验收依据。

### 任务 C / 通用流程与评估反馈

围绕视频分析、本地化或提示词等一个环节，记录可复现的失败与改进建议。明确是结构问题、证据问题、语义问题还是审美判断；不要把个人观感直接包装成量化效果。

### 材料怎样选择

只使用合成样例、公开可用材料或得到授权的素材。客户原稿、私人视频、内部语料与校准参数保持在受控范围；通用问题可以公开讨论，敏感原件无需跟着公开。

## ✦ 06 / 常见问题与公开入口

先让一条方法可复现，再考虑把多条方法串成工作流。

### SKILL 就是一段长提示词吗？

公开框架还包含任务路由、输入输出约定、流程、判据与校验。它关心的是一个工作步骤如何执行、如何检查以及如何交接，而不仅是怎样描述目标。

### 校验通过，结果就一定好吗？

不是。校验可以发现结构和部分规则错误，但语义、审美、语境和业务适用性仍需要人工判断。不能把结构正确等同于内容质量或生成效果已达标。

### 公开仓包含你们的内部语料吗？

不包含。框架、通用方法与合成样例公开；客户材料、内部数据和校准资产保持私有。需要特定数据的流程，应按相应权限与数据条件使用。

### 与 100xMCP 怎样配合？

SKILL 可以帮助分析素材、改编脚本和准备提示词；MCP 可以连接生成工具。具体任务也可以只使用其中一部分，不要求所有方法和工具一起运行。

### 从哪个 Skill 开始？

已有视频想分析，先看 video-reverse；已有脚本想整理，先看 segment；目标是另一市场表达，先了解 localize。不能确定时，先用路由入口描述当前材料和期望产物。
