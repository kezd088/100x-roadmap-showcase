## 适合谁，解决什么

需要把生成能力接入产品和自动化流程的开发者。

调用方式、任务状态、输出格式各异，业务代码容易和某个具体服务绑死。

## 可以怎样用

### 接收生成请求

围绕文字、参考图等输入组织请求，具体输入组合取决于模型能力。

### 跟踪生成任务

区分请求提交与最终结果，为调用方提供状态与错误反馈。

### 返回生成结果

把服务结果交付给调用方，由上层工作台或工具继续处理。

## 一个具体场景

业务系统需要一张商品场景图。调用方提交描述与参考素材，服务提供任务状态和最终结果。失败时，调用方需要根据反馈判断下一步如何处理。

*这是帮助理解产品用途的概念案例。*

明确生成规格与输入 → 确认允许接入的能力 → 提交任务并查询状态 → 取得并检查生成结果。

## 你会得到什么

可被业务应用使用的生成任务与结果。

## 在生态中的位置

API 关注调用与生成任务，ROUTE 关注候选线路、管理和判断。SPEED 与 MCP 分别提供工作台和 Agent 使用入口。这里说明产品职责，各产品的接入状态分别确认。

## 当前状态与入口

面向内部与受控接入的生成服务工程，已有图片、视频生成及兼容接口实现。具体接入方式按服务确认。

本目录就是公开产品介绍；具体接入经现有联系人确认。

## 可以从这些事参与

接口契约、任务状态、错误语义、结果可靠性。

通过现有联系人说明经历和想做的具体任务，确认范围与交付后开始。
