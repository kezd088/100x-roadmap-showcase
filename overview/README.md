## ✦ 01 / 为什么是一个产品生态

内容生产不是一个按钮。它包含理解材料、组织创意、调用生成、判断线路、检查结果和再次复用。

### 共同面向的问题

100x 面向内容创作者、跨境电商团队和开发者。创意与执行分散、生成任务难以跟进、方法难复用、服务选择缺少依据，是五个产品分别尝试解决的问题。

### 这份资料怎样读

把它当作产品与合作导航：先找到你正在处理的问题，再选择一本产品手册深入了解。各产品有不同的使用入口和开放状态，不需要先理解全部内部工程。

### 公开与受邀协作

这里公开产品介绍、概念图解和精选地图展示。内部工程、业务材料与运行信息按邀请访问。产品分工说明不是已完成生产联调的架构证明；使用前仍需核对具体产品状态。

## ✦ 02 / 五个产品，各自交付什么

这些产品可以分别了解。下面按“使用者、核心工作、得到的结果”说明分工。

![100xROADMAP 工作流程与角色图解](ecosystem.png)

### 100xSPEED / 面向创作者

在 Web 工作台准备创意、组织生成任务与管理资产。适合持续制作图片、视频素材的人；输出是可筛选、归档和继续迭代的素材及创意记录。当前核心区域为创意区、任务区和资产库。

### 100xAPI / 面向接入开发者

把图片与视频生成组织为服务接口，让业务围绕请求、任务状态与结果工作。适合把生成能力接入产品或流程的团队；当前服务面向内部与受控接入，具体契约按服务确认。

### 100xROUTE / 面向运行团队

集中理解模型、候选线路、配置、价格与运行依据。输出是可核对的目录和运行判断，帮助团队解释选择与变化；当前为线路控制台，对外商业分发与计费属于后续演进方向。

### 100xMCP / 面向 Agent 使用者

在 Codex 对话中查能力、查报价、带预算提交并取得生成结果。输出进入工作目录。客户端与插件公开，生成服务仍需内测接入；工具连接与宿主展示能力分别确认。

### 100xSKILL / 面向内容方法复用

把视频分析、脚本处理、表达改编和提示词准备变成可重复步骤。公开框架包含 8 个功能 Skill 与 1 个路由入口；结构化结果可以继续交给人、其他 Skill 或生成工具。

## ✦ 03 / 一个场景，怎样看清不同职责

示例：为一款无品牌保温杯准备目标市场的短视频素材。以下用于解释职责，不是已经联调完成的客户案例。

### 01 / 准备简报与可用材料

先说清受众、用途、商品事实、目标画幅与表达约束，选择获准使用的参考素材。缺少这些输入时，后续工具很难判断“什么结果算合适”。

### 02 / 用方法整理内容

SKILL 可以帮助分析参考、分段、改编表达和准备提示词。输出应保留依据、约束与未确认项，使后续制作知道哪些内容已经确认、哪些仍需人判断。

### 03 / 选择适合的生成入口

习惯可视工作台的人可以从 SPEED 准备方向并组织任务；习惯 Agent 对话的人可以从 MCP 查能力、确认报价与预算。两种入口代表不同工作习惯，不要求二者同时使用。

### 04 / 理解服务与线路的职责

API 关注生成请求和结果，ROUTE 关注候选线路与判断依据。它们帮助解释服务层的工作，但不能把角色图直接当成每次任务的真实调用链。

### 05 / 检查、筛选与交接

人工检查生成素材的主体、内容与规格，再决定保留、返修或舍弃。建议交付素材、使用说明与下一步修改点；不以生成数量或流畅表述代替内容质量。

## ✦ 04 / 按你的工作，选择阅读路径

先选一个入口完成小任务，再判断是否需要其他产品。

### 路径 A / 我想持续制作素材

先读 SPEED，理解创意、任务和资产如何衔接；如果前期内容分析或跨语言改编较多，再读 SKILL。建议准备一个清楚的素材简报，先走通一次生成与归档流程。

### 路径 B / 我已经在 Agent 中工作

先读 MCP，理解安装、接入、报价、预算和任务交付；再按内容需求选择 SKILL。第一次先查连接与能力，不生成，确认接入正常后再做一项有明确预算的任务。

### 路径 C / 我要把生成加入产品

先读 API，明确输入、任务状态、失败处理与结果交付；需要管理多个候选来源时，再读 ROUTE。先用一个获准的小场景验证契约，再讨论扩展。

### 路径 D / 我希望参与建设

先选你能贡献的产品和环节，阅读该册的任务示例。用一个具体问题、建议交付与检查方法开始讨论，比笼统说明“会 AI、想加入”更容易确定协作范围。

### 入口与权限分别确认

> SPEED 通过官网了解；MCP 与 SKILL 有公开仓；API 与 ROUTE 的接入按具体任务确认。ROADMAP 完整地图与成员资料通过邀请访问，公开介绍不自动授予内部仓库权限。

## ✦ 05 / 把参与意愿变成一项可交付工作

下面是合作方向与交付示例，供讨论使用；不代表招聘承诺、预算批准或内部访问授权。

### 创作与体验 / SPEED

围绕一个合成简报走完整流程，交付可复现体验报告；也可以研究任务状态反馈或素材查找，说明问题如何影响下一步工作。

### 契约与可靠性 / API

选择一种获准模式，交付输入输出约定、异常样例或结果检查方法。重点是让调用方理解任务真实状态，并能够取得可用结果。

### 目录与判断 / ROUTE

核对能力目录、价格口径或状态来源，交付有依据的差异清单与建议。对未知项保持明确，不把未经验证的数字写成结论。

### 工具与方法 / MCP、SKILL

MCP 方向可以做安装体验、任务反馈与文件交付；SKILL 方向可以做合成样例、输出契约与反例。每项工作都应说明输入、结果与检查方式。

### 协作的起点

说明经历、擅长方向与想解决的问题；一起确定任务范围、交付物、材料权限和检查方法；获得相应邀请后开展工作。最终是否完成与接受，由实际交付和人工评审决定。

## ✦ 06 / 常见问题与资料目录

这份总览用于认识生态；五本产品手册提供能力、案例、接入与参与细节。

### 这五个产品都已全面开放吗？

不是同一种开放状态。SPEED 有产品入口；MCP 客户端公开、服务内测；SKILL 框架公开；API 与 ROUTE 按受控方式接入。具体状态见各册说明。

### 它们已经组成自动完成的内容生产线吗？

本资料说明产品职责和可以怎样理解组合使用，不证明所有模块已经生产联调，也不承诺无需人工检查。每个实际流程需按接入与材料条件确认。

### 能从这里拿到完整源码或内部数据吗？

展示仓提供介绍、PDF、图解与精选展示。业务工程、客户材料、凭据、内部语料与运行资料保持私有，按具体协作权限访问。

### 怎样提出有效的反馈或合作？

选一个产品，说明具体场景、观察到的问题、可复现步骤或你能交付的结果。公开反馈使用合成或允许公开的材料，敏感细节通过已有授权渠道协作。
